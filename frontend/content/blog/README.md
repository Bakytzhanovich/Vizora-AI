# Как добавить статью в блог

Создай `.md` файл прямо в этой папке (`content/blog/`). Имя файла = slug статьи
(`voprosy-konsula-j1-interview.md` → `/blog/voprosy-konsula-j1-interview`).

## Frontmatter (обязательные поля)

```yaml
---
title: "Вопросы консула на визовом интервью J-1 Work and Travel"
description: "Краткое описание для превью и meta description (150-160 символов)"
date: "2026-08-23"
category: "j1"
keywords: ["j1 виза", "work and travel", "интервью консульство"]
---
```

После `---` пиши сам текст статьи обычным Markdown (заголовки `##`, списки, абзацы).

## Поле `category`

Допустимые значения: `"j1"` | `"b1b2"` | `"f1"` | `"general"`.

- **`j1`** — Work & Travel USA (виза J-1). Единственная категория с реальными
  статьями сейчас.
- **`b1b2`** — Туристическая виза (B1/B2). Запуск направления — 2027 Q1.
- **`f1`** — Учёба в США (виза F-1). Запуск направления — 2027 Q2-Q3.
- **`general`** — визово-нейтральный контент, не привязанный к конкретной
  программе (например «как вести себя на любом визовом интервью»,
  «что такое DS-160» и т.п.).

### Почему это поле уже здесь, хотя B1/B2 и F1 ещё не запущены

Vizora AI сейчас работает только с J-1, но в 2027 расширяется на туристические
(B1/B2) и учебные (F-1) визы. Категория заложена в структуру блога заранее —
это ничего не меняет для тебя, если пишешь только про J-1 (просто ставь
`category: "j1"`), но избавляет от переделки блога, когда появятся другие
направления.

**Когда B1/B2 или F1 запустятся — просто создавай файлы с
`category: "b1b2"` или `category: "f1"`.** Они автоматически появятся под
своей вкладкой на `/blog` (сейчас эти вкладки показывают заглушку
«Скоро появится»/пусто, потому что подходящих статей ещё нет) — трогать код
`app/blog/page.tsx` или `lib/blog.ts` не нужно.

## Не создавай пустые папки b1b2/ f1/

Все статьи, независимо от категории, лежат в одной папке `content/blog/` —
категория определяется полем `category` во frontmatter, а не расположением
файла. Подпапки `b1b2/`, `f1/` заводить не нужно ни сейчас, ни в будущем.
